# 麦肯锡风版式登记

每页使用 `data-layout="Cxx"`。版式服务内容，不允许为使用版式而编造数据。

| ID | 名称 | 适用内容 | 必须包含 |
|---|---|---|---|
| C01 | Centered Cover | 封面 | 居中大字主题、可选副标题、可选场景信息 |
| C02 | Executive Summary | 2—3条结论与建议 | 结论、依据、行动含义 |
| C03 | KPI Strip | 2—4个真实指标 | 数值、单位、范围、解释 |
| C04 | Evidence Chart | 单一比较关系 | 行动标题、图表、来源、So what |
| C05 | Two-Column Logic | 两组对照或问题/建议 | 分类口径和结论 |
| C06 | Issue Tree | 根因、驱动或逻辑分解 | 顶层问题、不重叠分支 |
| C07 | Findings Table | 3—7项发现 | 发现、证据、影响 |
| C08 | Options Matrix | 方案比较 | 统一维度、取舍、建议 |
| C09 | Roadmap | 3—6步实施计划 | 阶段、交付、责任或依赖 |
| C10 | Risks & Decisions | 管理层关注 | 风险、影响、措施、所需决策 |
| C11 | Appendix | 方法、口径、明细 | 标题和来源 |
| C12 | Section Divider | 章节切换 | 章节名、一句导语、章节编号 |
| C13 | Process Flow | 3—6步流程 | 顺序、责任、输入输出或依赖 |
| C14 | Image Evidence | 截图、照片或案例证据 | 图片、图注、证据含义、来源 |
| C15 | Data Hero | 一个关键数字 | 数值、单位、范围、解释与来源 |
| C16 | Closing Ask | 收束或管理层请求 | 核心结论、下一步、责任或决策请求 |

没有真实数据时禁止使用 C03/C04 伪造量化结论；只有存在统一评价维度时才用 C08；路线图用于实施顺序，不用于普通待办清单。

## 版式多样性

- 7—8页至少使用5个不同版式；10页以上至少使用7个不同版式。
- 连续三页不得使用相同主体结构，例如连续三页“三列卡片”。
- 单张关键图片使用C14；关键单值使用C15，不要用普通卡片把它缩小。
- 章节很多时可使用C12建立节奏，但章节页不承载正文内容。
- 收尾优先使用C10或C16，明确风险、行动或所需决策，不使用空泛“谢谢”。

## 低密度页面

当有效内容只有一句结论、一个关键数字或不超过三行短文时，不扩写空洞内容，也不把少量文字缩在左上角：

- 使用 `.center-stage` 让内容在安全区水平、垂直居中。
- 结论使用 `.center-title`，推荐 `clamp(48px, 6vw, 92px)`。
- 补充说明使用 `.center-copy`，控制在1—3行。
- 单一数字优先使用C15；单一句子可使用C12或低密度C16。
- 只有在内容之间存在真实并列关系时才使用卡片。

完整C01—C16实现参考 `assets/layout-gallery-consulting.html`。

## C13流程页构图规则

- 流程必须呈现“步骤之间的关系”，不能只是一排等高文字卡片。
- 步骤说明较短时，在流程下方增加一条贯穿全流程的结果、输入输出或价值收束带；该收束带必须提供新信息。
- 当一排流程导致下半页空置时，改用2×2、纵向阶梯或“流程 + 结果带”，让主体覆盖安全区约65%—85%的高度。
- 箭头与连接线应落在模块中心线上，不能悬浮在模块间或与正文争夺注意力。

## C01 首页硬规则

- 主题名是页面最大元素，水平和垂直居中。
- 主题使用直接、易懂的名称，如“AI如何改变财务工作”“新产品发布”“市场进入战略”。
- 不使用行动标题，不把执行摘要塞入首页。
- 副标题可说明范围或展示承诺，不得超过一行。
- 部门、日期、报告期、版本和演讲者均为可选元信息；不自动生成，不得与主题争夺视觉注意力。
